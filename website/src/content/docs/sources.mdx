## Adding a source

Choose a protocol in the side panel, then pick a discovered source. NDI and Syphon sources are discovered continuously;
capture devices refresh on demand.

## Reconnecting

If a source disappears, Multiviewer keeps it on the canvas and reconnects when it returns. Its position and label are
preserved.

## GPU sources

Syphon and Spout deliver a texture straight to the compositor, with no CPU copy. The other protocols deliver frames that
the compositor uploads to the GPU once per frame.

## Common settings

Every source has the same settings in its **Properties** panel, whatever the protocol.

### Screen capture

Screen capture covers macOS and Windows, with a slightly different set of settings on each.

On macOS, granting Screen Recording permission is required; the list of displays and windows stays empty until it is granted. A "Privacy and Security" popup will appear when you select the protocol the first time. Agreeing to the popup will require an app restart.

### VNC

VNC servers are not discovered, so a connection is made by hand: pick **+ New VNC Source** in the source list, then fill in the address under **Protocol Settings**.

The connection authenticates one of two ways, depending on whether **Username** is filled in:

- **Username and password**: the password is that account's login password and the session signs in as the account. This is Apple Remote Desktop authentication, which macOS Screen Sharing offers; a server that does not offer it falls back to the VNC password below.
- **Password only**: the password is the server's own VNC password, which identifies no user.

The password is encrypted with a key built into the app, so it is not readable at a glance in a project file, but
anyone who has the app and the file can recover it. The session is always shared, so connecting never disconnects
another viewer.

Multiviewer only displays the remote screen: it never sends keystrokes or clicks, so it cannot be used to control the
host. The one exception is **Keep awake**, described below.

<SettingsTable name="VNC" direction="input" />

#### Idle screens go black

Many servers blank the screen after a few minutes with no input, which a passive viewer sees as a black tile: an update
request does not count as input, only a pointer or key event does. **Keep awake** sends a pointer event every couple of
seconds: it parks the remote cursor near the top-left corner and moves it one pixel back and forth, which resets that
machine's idle timer. Two things follow: the cursor is pulled to that corner, and the machine will not blank or lock while
it is idle. So it is off by default and worth deciding per machine.

#### macOS Screen Sharing

With a username and password the session is signed in as that account, so it reaches that account's desktop, including
when the Mac sits at the login window and nobody is logged in. The credentials are encrypted on the wire; the video
session itself is not. The Mac may also show a local prompt asking whoever is at the console to approve the connection.

The password-only mode identifies no user, so macOS shows the **login window** rather than the desktop of whoever is
logged in. On a Mac you administer, have the built-in server attach to the console session:

```sh
sudo defaults write /Library/Preferences/com.apple.RemoteManagement VNCAlwaysStartOnConsole -bool true
```

Then restart Screen Sharing or reboot. This lets anyone holding the VNC password reach the logged-in desktop directly, so weigh it against your security policy.

### RDP

RDP servers are not discovered either: pick **+ New RDP Source** in the source list, then enter the address and the account credentials under **Protocol Settings**.

Unlike VNC, RDP authenticates a real user account, and there is no separate view-only mode: the credentials decide which session is shown. The password is encrypted with a key built into the app, so it is not readable at a glance in a project file, but anyone who has the app and the file can recover it.

Multiviewer only displays the remote screen: it never sends keystrokes or clicks, so it cannot be used to control the
host. Two consequences are worth knowing before pointing it at a machine someone is using:

- A host allows one session per account. If that account is already logged in elsewhere, connecting takes the session
  over. Use a dedicated account, or expect to disconnect the other session.
- Closing the app disconnects the session rather than signing it out, so whether the machine is left locked or logged
  off follows the host's own policy.

The server certificate is always accepted, which is what makes a host using its own self-signed certificate connectable.
RDP over TLS still encrypts the session, but it does not prove the host is the one it claims to be: rely on a trusted
network.

**Size** is the desktop resolution requested from the host. A host may also keep the resolution of
a session that is already running.

### Timecode

Display a received timecode as a text card. It holds the last value when the signal stops, and shows a placeholder in
the selected display shape before the first value. Nothing is generated locally.

Add one with **Protocol** set to **Timecode** and **Source** set to **+ New Timecode Source**. The input is configured
under **Protocol Settings**:

- **Art-Net**: **Bind** (default `0.0.0.0`), **Port** (default `6454`) and **StreamID** (default `0`). One source binds
  a given port; share it across placements or give a second source another port.
- **MTC**: pick a **MIDI input**. The port is stored by name, so a project opened on another computer reconnects to the
  same-named input; reselect it if that machine exposes a different name. The rate (24, 25, 29.97 DF or 30) is
  read from the messages. Full-frame and quarter-frame messages are both supported.

**Display** selects the fields drawn:

| Display | Shows |
|---|---|
| `HH:MM:SS:FF` | Full label, with `;` instead of `:` for drop-frame |
| `HH:MM:SS.mmm` | Hours, minutes, seconds, and the received label's frame part as milliseconds |
| `HH:MM:SS` | Hours, minutes, seconds |
| `HH:MM` | Hours and minutes |
| `MM:SS` | Minutes and seconds |
| Frames | Elapsed frame count, excluding skipped drop-frame numbers |
| Seconds | Elapsed seconds as a decimal |

The remaining rows set frame width and height (capped at 1920x1080 for Timecode), font size, text and background
colors, and alignment.
